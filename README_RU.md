# WHAT - Веб-инструментарий для анализа HDL

[中文](README.md) | [English](README_EN.md) | [日本語](README_JA.md) | [Français](README_FR.md) | [Deutsch](README_DE.md) | [Русский](README_RU.md)

WHAT — это веб-инструмент для анализа кода и сигналов HDL (язык описания аппаратуры).

## Мотивация проекта

Первоначальной мотивацией этого проекта было тестирование возможностей программирования с помощью ИИ. Как инженеру-аппаратчику, мне часто приходится одновременно просматривать исходный код и сигналы симуляции для отладки и анализа. Однако на рынке не хватает инструментов с открытым исходным кодом, которые могли бы тесно интегрировать исходный код и сигналы. Коммерческие инструменты дорогие и негибкие, а существующие решения с открытым исходным кодом часто фрагментированы и не могут образовать полноценный рабочий процесс.

Поэтому у меня возникла идея использовать ИИ для разработки инструмента анализа, соответствующего моим привычкам использования. Удивительно, но основной код этого проекта был полностью написан ИИ — от архитектурного проектирования до конкретной реализации, от разметки интерфейса до функциональной логики. Разработка основных функций заняла около 2 недель, а последующее исправление ошибок и оптимизация функциональной архитектуры заняли еще около 2 недель. Такая эффективность разработки невообразима в традиционных моделях программирования и полностью демонстрирует скачкообразный рост эффективности программирования с помощью ИИ.

Особая благодарность:
- **Trae IDE** за предоставление отличной среды разработки и бесплатной вычислительной мощности ИИ
- **Doubao-seed-2.0**, **Kimi K2.5**, **GLM-5** и другим крупным моделям за предоставление мощных возможностей генерации кода

## Особенности функций

### Анализ исходного кода
- **Поддержка Verilog/SystemVerilog**: Полная подсветка синтаксиса и сворачивание кода
- **Просмотр иерархии проекта**: Визуальное отображение иерархии инстанцирования модулей
- **Интеллектуальная навигация по коду**: Поддержка перехода к определению, трассировки драйверов и нагрузок
- **Функция закладок**: Быстрая маркировка и переход к ключевым позициям кода
- **История навигации**: Поддержка просмотра позиций кода вперед/назад

### Анализ сигналов
- **Поддержка файлов сигналов FST**: Высокопроизводительное чтение больших файлов сигналов
- **Отображение нескольких сигналов**: Поддержка управления группами сигналов и настройки ширины столбцов
- **Гибкое масштабирование и панорамирование**: Масштабирование колесиком мыши, перетаскивание, полноэкранное соответствие
- **Операции с курсором**: Щелчок для установки позиции курсора, точное отображение значений сигналов
- **Функция поиска значений**: Поддержка поиска шаблонов в различных форматах (двоичный, шестнадцатеричный, восьмеричный)
- **История поиска**: Сохранение истории поиска для быстрого повторного поиска

### Интеграционные функции
- **Связь исходного кода и сигналов**: Двойной щелчок по сигналу в коде для просмотра его источника драйвера
- **Браузер проекта**: Быстрое добавление сигналов в окно сигналов из дерева иерархии модулей
- **Управление сессиями**: Сохранение и восстановление полного рабочего состояния
- **Поддержка нескольких вкладок**: Одновременное открытие нескольких окон исходного кода и сигналов

## Быстрый старт

### Требования

- **Node.js** 18+ (для веб-клиента)
- **Rust** (для сервера)
- **CMake** + **Компилятор C++** (для интерпретатора)
- **Surelog** (для интерпретатора, парсинг SystemVerilog)

### Шаги запуска

1. **Запуск сервера**
   ```bash
   cd server
   cargo run --release -- --kdb-dir /path/to/kdb --wave-dir /path/to/waves --port 8080
   ```

2. **Запуск веб-клиента**
   ```bash
   cd web-client
   npm install
   npm run dev
   ```

3. **Доступ к интерфейсу**
   
   Откройте браузер и перейдите по адресу `http://localhost:3000`

## Руководство пользователя

### 4.1 Интерпретатор

Интерпретатор используется для анализа исходного кода Verilog/SystemVerilog и генерации файлов KDB (база знаний). Файлы KDB содержат:
- Определения модулей и иерархию инстанцирования
- Объявления сигналов и отношения соединений
- Информацию о трассировке драйверов/нагрузок

#### 4.1.1 Требования

- **Ubuntu 22.04+** или **WSL2 (Ubuntu)**
- **CMake** 3.20+
- **GCC/G++** 11+ или **Clang** 14+
- **Protocol Buffers** (protobuf)
- **zstd** (опционально, для сжатия)

#### 4.1.2 Установка зависимостей

Установка зависимостей компиляции на Ubuntu/WSL:

```bash
# Обновление списка пакетов
sudo apt-get update

# Установка базовых инструментов компиляции
sudo apt-get install -y build-essential cmake git

# Установка Protocol Buffers
sudo apt-get install -y protobuf-compiler libprotobuf-dev

# Установка zstd (опционально, для сжатия)
sudo apt-get install -y libzstd-dev

# Установка других зависимостей
sudo apt-get install -y python3 python3-pip pkg-config
```

#### 4.1.3 Компиляция

**Шаг 1: Клонирование репозитория**
```bash
cd /path/to/your/workspace
git clone <repository-url>
cd webhwd
```

**Шаг 2: Установка зависимостей**
```bash
# Обновление списка пакетов
sudo apt-get update

# Установка базовых инструментов компиляции
sudo apt-get install -y build-essential cmake git

# Установка Protocol Buffers
sudo apt-get install -y protobuf-compiler libprotobuf-dev

# Установка zstd (опционально, для сжатия)
sudo apt-get install -y libzstd-dev
```

**Шаг 3: Компиляция проекта**
```bash

./build.sh
```

Примечания по компиляции:

- Результаты компиляции кэшируются, последующие компиляции будут быстрее
- После компиляции исполняемые файлы находятся в:

```bash
./build_new/interpreter/kdb_viewer --help
```

#### 4.1.4 Базовое использование

**Анализ файла Verilog для генерации KDB:**

```bash
# Базовое использование
./build_new/interpreter/hwda_interpreter design.v --output design.kdb

# Указание топ-модуля
./build_new/interpreter/hwda_interpreter design.v --output design.kdb -top top_module

# Добавление пути включения
./build_new/interpreter/hwda_interpreter design.v --output design.kdb +incdir+./include

# Использование подробного режима для просмотра детальных логов
./build_new/interpreter/hwda_interpreter design.v --output design.kdb --verbose
```

**Общие опции:**

| Опция | Описание |
|-------|----------|
| `-o, --output <path>` | Указать путь к выходному файлу KDB (по умолчанию: design.kdb) |
| `-top <module>` | Указать топ-модуль |
| `+incdir+<dir>` | Добавить путь включения |
| `-y <path>` | Добавить директорию библиотеки |
| `-v <file>` | Добавить файл библиотеки |
| `-D<name>=<value>` | Определить макрос |
| `-z, --compress` | Включить сжатие (включено по умолчанию) |
| `-Z, --no-compress` | Отключить сжатие |
| `-V, --verbose` | Показать детальную отладочную информацию |
| `-h, --help` | Показать справочную информацию |

#### 4.1.5 Просмотр файлов KDB

Используйте инструмент kdb_viewer для просмотра содержимого сгенерированного файла KDB:

```bash
# Просмотр информации о файле KDB
./build_new/interpreter/kdb_viewer design.kdb

# Список всех модулей
./build_new/interpreter/kdb_viewer design.kdb --modules

# Список всех сигналов
./build_new/interpreter/kdb_viewer design.kdb --signals

# Просмотр информации о драйвере конкретного сигнала
./build_new/interpreter/kdb_viewer design.kdb --driver work@top.signal_name

# Вывод в формате JSON
./build_new/interpreter/kdb_viewer design.kdb --json
```

#### 4.1.6 Формат файла KDB

KDB (база знаний) — это пользовательский бинарный формат, содержащий:

- **Информация о модулях**: Определения модулей, иерархия инстанцирования, параметры
- **Информация о сигналах**: Объявления сигналов, разрядность, типы (wire/reg/parameter и т.д.)
- **Отношения соединений**: Информация о драйверах и нагрузках сигналов
- **Позиции исходного кода**: Имена файлов, номера строк для перехода к исходному коду

Файлы KDB используют сериализацию Protocol Buffers и опционально сжатие zstd.

#### 4.1.7 Пример использования

```bash
# Анализ файла Verilog для генерации KDB
./build_new/interpreter/hwda_interpreter tests/simple.v --output tests/simple.kdb

# Просмотр информации о сгенерированном файле KDB
./build_new/interpreter/kdb_viewer tests/simple.kdb

# Просмотр информации о драйвере конкретного сигнала
./build_new/interpreter/kdb_viewer tests/simple.kdb --driver work@top.sum
```

Подробные инструкции по использованию см. в `interpreter/README.md`.

### 4.2 Сервер

Сервер предоставляет HTTP API для:
- Обслуживания файлов KDB
- Обслуживания файлов сигналов (формат FST)
- Предоставления интерфейсов поиска и запроса сигналов
- Поддержки двух бэкендов чтения FST: fstapi (по умолчанию) и fst-reader

#### 4.2.1 Требования

**Windows:**
- **Rust** 1.70+ (установлен через rustup)
- **LLVM/Clang** (для bindgen бэкенда fst-reader)
- **vcpkg** (для управления зависимостями C++)

**Ubuntu/WSL:**
- **Rust** 1.70+ 
- **LLVM/Clang** 
- **pkg-config**
- **libzstd-dev** (опционально, для сжатия)

#### 4.2.2 Шаги компиляции Windows

1. **Установка Rust**
   ```powershell
   # Установка через rustup
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   # Или скачать установщик с https://rustup.rs/
   ```

2. **Установка LLVM/Clang**
   - Скачать LLVM с https://github.com/llvm/llvm-project/releases
   - Распаковать в `C:\Users\<username>\Downloads\clang+llvm-<version>-x86_64-pc-windows-msvc`
   - Установить переменную окружения: `LIBCLANG_PATH=C:\path\to\llvm\bin`

3. **Установка vcpkg**
   ```powershell
   git clone https://github.com/Microsoft/vcpkg.git C:\path\to\vcpkg
   cd C:\path\to\vcpkg
   .\bootstrap-vcpkg.bat
   ```

4. **Компиляция сервера**
   ```powershell
   cd server
   $env:VCPKG_ROOT="C:\path\to\vcpkg"
   $env:LIBCLANG_PATH="C:\path\to\llvm\bin"
   cargo build --release
   ```
   
   После компиляции исполняемый файл находится в: `target\release\hwda-server.exe`

#### 4.2.3 Шаги компиляции Ubuntu/WSL

1. **Установка зависимостей**
   ```bash
   sudo apt-get update
   sudo apt-get install -y build-essential pkg-config libzstd-dev
   
   # Установка Rust
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   source $HOME/.cargo/env
   
   # Установка LLVM/Clang
   sudo apt-get install -y llvm libclang-dev
   ```

2. **Компиляция сервера**
   ```bash
   cd server
   cargo build --release
   ```
   
   После компиляции исполняемый файл находится в: `target/release/hwda-server`

#### 4.2.4 Базовое использование

**Запуск сервера:**

```bash
# Базовое использование (с использованием бэкенда fstapi по умолчанию)
./hwda-server --kdb-dir /path/to/kdb --wave-dir /path/to/waves --port 8080

# Использование бэкенда fst-reader
./hwda-server --kdb-dir /path/to/kdb --wave-dir /path/to/waves --fst-backend fst-reader

# Включение детальных отладочных логов
./hwda-server --kdb-dir /path/to/kdb --wave-dir /path/to/waves --log-level debug --verbose

# Очистка кэша при запуске
./hwda-server --kdb-dir /path/to/kdb --wave-dir /path/to/waves --clear-cache-on-startup

# Включение службы статических файлов веб-клиента
./hwda-server --kdb-dir /path/to/kdb --wave-dir /path/to/waves --web-dir /path/to/web-client/dist
```

**Общие опции:**

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `--kdb-dir <path>` | Директория файлов KDB | `./kdb` |
| `--wave-dir <path>` | Директория файлов сигналов | `./waves` |
| `--port <port>` | Порт службы | `8080` |
| `--host <host>` | Адрес привязки | `0.0.0.0` |
| `--fst-backend <backend>` | Бэкенд чтения FST (`fstapi` или `fst-reader`) | `fstapi` |
| `--log-level <level>` | Уровень логов (`trace`, `debug`, `info`, `warn`, `error`) | `info` |
| `--verbose` | Включить детальный отладочный вывод (эффективно только при `log-level=debug`) | `false` |
| `--web-dir <path>` | Директория статических файлов веб-клиента | - |
| `--clear-cache-on-startup` | Очистить все кэши при запуске | `false` |
| `--enable-cors` | Включить CORS | `true` |
| `--cache-capacity-mb <size>` | Ёмкость кэша LRU (МБ) | `512` |

**Просмотр справки:**

```bash
./hwda-server --help
```

#### 4.2.5 Выбор бэкенда FST

Сервер поддерживает два бэкенда чтения FST:

1. **fstapi** (по умолчанию)
   - Использует библиотеку C libfst от GTKWave
   - Хорошая совместимость, поддерживает все функции FST
   - Требует среду компиляции C++

2. **fst-reader** (чистый Rust)
   - Чистая реализация на Rust, без зависимостей C++
   - Лучшая производительность, меньшее использование памяти
   - Включить с помощью `--fst-backend fst-reader`

**Пример переключения бэкенда:**
```bash
# Использование бэкенда fstapi (по умолчанию)
./hwda-server --wave-dir ./waves

# Использование бэкенда fst-reader
./hwda-server --wave-dir ./waves --fst-backend fst-reader
```

#### 4.2.6 API-интерфейсы

Сервер предоставляет следующие основные API:

- `GET /api/kdb` - Список всех файлов KDB
- `GET /api/kdb/{name}/signals` - Получить список сигналов в KDB
- `GET /api/wave` - Список всех файлов сигналов
- `GET /api/wave/{name}/signals` - Получить список сигналов в файле сигналов
- `GET /api/wave/{name}/lod/{lod}/tile/{start}/{span}/{count}/signals/{signal_ids}/data` - Получить данные сигналов

Подробная документация API см. в `server/API.md`.

### 4.3 Веб-клиент

#### 4.3.1 Подключение к серверу

При первом открытии приложения необходимо подключиться к серверу:

1. Введите адрес сервера и порт в диалоге подключения
2. Адрес по умолчанию — `localhost:8080`
3. Нажмите кнопку "Connect"
4. После успешного подключения список доступных файлов KDB отобразится автоматически

#### 4.3.2 Загрузка файлов KDB и сигналов

**Загрузка файла KDB:**
1. Нажмите меню **File → Open KDB**
2. Выберите файл KDB из списка
3. После загрузки иерархия модулей отобразится в браузере проекта слева

**Загрузка файла сигналов:**
1. Нажмите меню **File → Open Waveform**
2. Выберите файл сигналов (формат FST) из списка
3. Или выберите "Use Mock Data" для использования смоделированных данных для тестирования

#### 4.3.3 Браузер проекта

Браузер проекта находится в левой панели, отображая иерархию проекта:

- **Дерево модулей**: Отображение топ-модулей и экземпляров подмодулей
- **Список сигналов**: После выбора модуля отображаются все сигналы этого модуля
- **Функция поиска**: Введите имя сигнала или модуля в поле поиска для фильтрации

**Способы работы:**
- Щелчок по модулю: Отображение сигналов этого модуля в списке сигналов
- Двойной щелчок по модулю: Открытие исходного кода этого модуля
- Двойной щелчок по сигналу: Добавление сигнала в текущее окно сигналов
- Контекстное меню: Дополнительные опции работы

#### 4.3.4 Окно исходного кода

Окно исходного кода используется для просмотра кода Verilog/SystemVerilog:

**Базовые функции:**
- Подсветка синтаксиса
- Сворачивание кода (блоки module, always, begin-end)
- Отображение номеров строк

**Трассировка драйверов/нагрузок:**
1. Щелкните по имени сигнала в коде
2. Выберите "Find Drivers" или "Find Loads" во всплывающем меню
3. Результаты трассировки отобразятся в окне сообщений внизу
4. Двойной щелчок по результатам трассировки для перехода к соответствующей позиции исходного кода

**Функция закладок:**
- Нажмите меню **Navigate → Add Bookmark** для добавления закладки
- Закладки отображаются в панели закладок справа
- Двойной щелчок по закладке для быстрого перехода к соответствующей позиции кода

**История навигации:**
- Кнопки ← → на панели инструментов для навигации вперед/назад
- Поддержка истории навигации между файлами

#### 4.3.5 Окно сигналов

Окно сигналов используется для просмотра сигналов симуляции:

**Управление сигналами:**
- Перетаскивание сигналов из браузера проекта в окно сигналов
- Двойной щелчок по сигналам в браузере проекта для добавления к сигналам
- Использование функции группировки сигналов для организации сигналов
- Правый щелчок по сигналам для удаления или перемещения

**Операции просмотра:**
- **Масштабирование**: Колесико мыши или кнопки +/- на панели инструментов
- **Панорамирование**: Перетаскивание области сигналов
- **Полноэкранный режим**: Нажмите кнопку "Fit" на панели инструментов
- **Операции с курсором**: Щелчок по сигналу для установки позиции курсора

**Поиск значений:**
1. Нажмите кнопку "Search" на панели инструментов
2. Введите значение для поиска (поддерживается двоичный, шестнадцатеричный и т.д.)
3. Результаты поиска будут выделены

**Отображение времени:**
- Панель инструментов отображает время текущей позиции курсора
- Возможность ручного ввода значения времени для перехода к указанной позиции

**Поддержка нескольких окон:**
- Нажмите кнопку "+" для добавления нового окна сигналов
- Каждое окно может отображать различные комбинации сигналов
- Поддержка одновременного открытия нескольких окон исходного кода

#### 4.3.6 Табличное представление

Табличное представление отображает значения сигналов в табличном формате для определенного диапазона времени, подходящее для просмотра и анализа состояний сигналов:

**Создание табличного представления:**
- Нажмите кнопку "+" на панели инструментов и выберите "Table" для создания нового табличного представления
- При создании табличного представления, когда окно сигналов активно, автоматически наследуется:
  - Текущий диапазон времени окна сигналов (View Start / View End)
  - Все сигналы из развернутых групп
  - Формат отображения (Radix) для каждого сигнала
  - Настройки префикса сигналов

**Управление сигналами:**
- Перетащите сигналы из браузера дизайна в табличное представление
- Дважды щелкните сигналы в браузере дизайна, чтобы добавить их в таблицу
- Нажмите кнопку "×" в заголовке столбца, чтобы удалить сигнал
- Перетащите заголовки столбцов, чтобы изменить порядок сигналов

**Настройки диапазона времени:**
- Установите диапазон времени в полях ввода "Start" и "Span" на панели инструментов
- Нажмите кнопку "Apply", чтобы применить новый диапазон времени и получить данные
- Поддержка разбиения на страницы, используйте кнопки "Previous" и "Next" для навигации
- Нажмите кнопку "Continue", чтобы получить больше данных (если доступно)

**Настройки формата отображения:**
- Нажмите стрелку раскрывающегося списка в заголовке столбца, чтобы открыть меню выбора формата
- Поддержка отображения в двоичном (BIN), восьмеричном (OCT), десятичном (DEC) и шестнадцатеричном (HEX) форматах
- Каждый столбец сигнала может быть настроен независимо

**Фильтрация метаданных:**
- Фильтрация по характеристикам значений сигналов: состояние X, состояние Z, смешанное состояние, переход, переключение
- Несколько условий фильтрации объединяются логикой "ИЛИ"

**Фильтрация столбцов:**
- Введите условия фильтрации в поле ввода заголовка столбца
- Поддержка фильтрации по шестнадцатеричным значениям (например, `0x1a`)

#### 4.3.7 Окно сообщений

Окно сообщений находится в нижней панели:

- **Результаты трассировки драйверов**: Отображение источников драйверов сигналов
- **Системные сообщения**: Отображение результатов операций и информации об ошибках
- **Двойной щелчок для перехода**: Двойной щелчок по результатам трассировки для перехода к соответствующему коду

#### 4.3.8 Управление сессиями

**Сохранение сессии:**
1. Нажмите меню **File → Save Session**
2. Введите имя сессии
3. Сохраняемое содержимое включает:
   - Информацию о подключении к серверу
   - Текущие загруженные файлы KDB и сигналов
   - Все открытые окна исходного кода
   - Все открытые окна сигналов (включая списки сигналов)
   - Все открытые табличные представления (включая списки сигналов и диапазоны времени)
   - Закладки

**Восстановление сессии:**
1. Нажмите меню **File → Restore Session**
2. Выберите сохраненную сессию из списка
3. Система автоматически выполнит:
   - Подключение к серверу
   - Загрузку файлов KDB и сигналов
   - Восстановление всех окон и закладок

**Управление сессиями:**
- Возможность удаления ненужных сессий в диалоге сохранения/восстановления
- Поддержка поиска сохраненных сессий
- Данные сессии хранятся в LocalStorage браузера

## FAQ

### В: Не удалось подключиться к серверу?

1. Убедитесь, что сервер запущен
2. Проверьте правильность адреса и порта сервера
3. Проверьте настройки брандмауэра
4. Просмотрите консоль браузера на наличие сообщений об ошибках

### В: Загрузка сигналов медленная?

1. При большом файле сигналов первоначальная загрузка требует скачивания и распаковки
2. Система автоматически кэширует загруженные данные
3. Последующие обращения будут быстрее

### В: Как сохранить мое рабочее состояние?

Используйте функцию **File → Save Session** для сохранения всех текущих окон и настроек, затем быстро восстановите через **Restore Session** в следующий раз.

### В: Какие браузеры поддерживаются?

- Chrome 90+
- Firefox 90+
- Safari 15+
- Edge 90+

Требуется поддержка WebGL 2.0 и WebAssembly.

## Известные проблемы

### Проблемы качества кода
- **Хаос структуры кода**: Поскольку код в основном сгенерирован ИИ, он имеет проблемы с повторением и организацией. Некоторые реализации функций чрезмерно сложны с высокой связностью между модулями. Это важная проблема, которую текущие модели и инструменты программирования с помощью ИИ должны продолжать решать.

### Проблемы производительности
- **Потребление памяти интерпретатором**: Для больших проектов анализ интерпретатором занимает много времени и потребляет слишком много памяти, что может привести к ошибкам OOM (Out of Memory). Рекомендуется обрабатывать большие проекты партиями или увеличить системную память.
- **Плавность рендеринга веб-клиента**: Рендеринг WebGL2 еще не реализован, для рендеринга сигналов используется только Canvas2D.

### Полнота функций
- **Недостаточное покрытие тестами**: Многие функции не имеют достаточного тестирования и могут иметь неправильную обработку граничных случаев. Приветствуются вклады сообщества в виде тестовых случаев и отчетов об ошибках.
